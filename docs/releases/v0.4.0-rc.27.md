# O3K v0.4.0-rc.27

PP.6 Stage 2 installed-release qualification candidate. PP.6 remains BLOCKED.
This is not PP.6 final acceptance, a production release, PP.7 authorization,
production restore activation, or Araf integration. These notes prepare the
candidate only; they do not authorize a tag or publication.

## Candidate source changes

The candidate is based on the protected merge of PRs #1212, #1213, and #1214,
followed by one focused version-bump and evidence update:

- #1212 adds signed journal restart coverage.
- #1213 repairs isolated qualification guest provisioning and ownership-checked
  cleanup, including explicit virtio `vda` root selection, cloud-init completion,
  DHCP lease parsing, ext4 validation, and run-owned resource identity checks.
- #1214 makes the packaged A10 verifier self-contained and executes it from an
  extracted release archive in a clean environment. The fail-closed regression
  matrix covers archive/checksum corruption, modified content, A10 markers,
  embedded test keys, publisher symbols, missing or failing inspection tools,
  and the excluded production migration command.
- Cargo metadata/lock, installer pin and embedded worker asset, Helm appVersion,
  Docker build defaults, qualification fixtures, and installer documentation
  are aligned to `0.4.0-rc.27`.
- The PP.6 PostgreSQL outage-test cleanup verifies absence through a successful
  full-ID Docker listing after inspect fails; this is test-only and does not
  change shipped runtime behavior.

The release build remains based on Debian 12 and retains the existing glibc
baseline check. The archive verifier is self-contained and must pass after
extracting the candidate archive outside the source checkout.

## Qualification scope

The proposed candidate is intended only to begin installed-release Q1/Q2
qualification on authenticated Debian 12 and Ubuntu 24.04 guests using the
explicitly authorized disposable KVM host and the read-only host preflight.
The #1213 local provisioning/cleanup result is E3 infrastructure evidence and
does not establish installed-release acceptance. E1 source tests and E2
protected CI likewise do not substitute for E4 authenticated installed-release
evidence or E5 physical host power-loss evidence.

## Explicit unsupported behavior

- The production bundle does not include `o3k recovery-migrate-v2`; its
  publisher remains disabled. Qualification-only publisher execution is not a
  production capability.
- Signed journal-v2 is an authenticated consumer, not an operational restore
  capability.
- PostgreSQL restore-target mutation and recovered-controller activation are
  not authorized.
- The rc.26 verifier defect is not repaired in place; rc.26 remains immutable.
- This candidate does not certify PP.6, claim production readiness, claim full
  OpenStack/Horizon parity, authorize PP.7, or include Araf integration.
- Authentication of release assets alone does not count as guest verifier,
  installation, Q1/Q2, E4, or E5 evidence.

The minimum declared upgrade source remains `v0.4.0-rc.5`; this does not assert
that a full upgrade/rollback journey has passed. The published `alpha` channel
remains unchanged.

Publication, if later authorized, must use the protected release workflow and
its required `release` environment approval, GitHub OIDC, Sigstore provenance,
signed digest manifest, and immutable prerelease policy. Any failure requires
a successor candidate; published assets are never repaired in place.
