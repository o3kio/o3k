# O3K v0.4.0-rc.1 — PP.1 release candidate (prerelease)

This is the first downloadable, versioned O3K release candidate, produced by
PP.1 (issue #970) from the frozen PP.0 product baseline (issue #969,
SPEC-0048, contracts/release-bundle-v1.yaml). It is a **prerelease**: it is
not release-gate approved (docs/release-tracker.md remains blocked; issues
#93/#94 own release-gate execution and publication) and it makes no
installation, scale, or production claims.

## What this candidate is

- Built from an exact clean protected-main source SHA; every asset is bound
  to that SHA via `manifest.json`, `SHA256SUMS`, the SPDX SBOM, and the
  published provenance/signature material.
- Bundle contents implement `contracts/release-bundle-v1.yaml`:
  `install.sh` (byte-identical export of `packaging/get-o3k.sh`, pinned to
  this version), `o3k-0.4.0-rc.1-linux-x86_64.tar.gz` (+ `.sha256`),
  `manifest.json` (source commit, schema_version, `upgrade_from.min_version`,
  installer digest), `SHA256SUMS`, `sbom.spdx.json`, and
  `provenance/signature material` (`release-digests.txt` + `release-digests.sig`
  + `provenance.json` + `release-verify.pub`).
- Runtime inventory covers `o3k-demo-v1` (`o3kd`, `o3k`, `o3k-compute`,
  libvirt profile) and ships the `o3k-network` execution agent binary plus
  its systemd unit for the `o3k-small-edge-v1` boundary. No target-host
  compilation: the installer fails closed when a required prebuilt binary is
  absent from a release bundle.
- GitHub Releases is the canonical public distribution source; get.o3k.io
  remains a convenience 302 redirect only.

## Explicitly not claimed

- successful one-line fresh-host installation (PP.2 owns install evidence
  through the canonical P15 init/join path);
- P15.7 completion claims beyond the recorded protected evidence;
- Small Edge support (the 1–20 hypervisor envelope is a hardening target);
- Araf deployment (Araf remains a separately versioned client);
- production readiness, GA, HA, live migration, or automatic evacuation.

## Verification

Integrity (every published asset, against the certified digests):

```sh
sha256sum -c --strict release-digests.txt
```

Authenticity (ed25519 release key, from any checkout of this repository or
the published `release-verify.pub`):

```sh
openssl pkeyutl -verify -pubin -inkey release-verify.pub -rawin \
  -in release-digests.txt -sigfile release-digests.sig
```

The installer itself additionally verifies the tarball's published `.sha256`
before extraction and the bundle `SHA256SUMS` via `verify-release-bundle.sh`.
