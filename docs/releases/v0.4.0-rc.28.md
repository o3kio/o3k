# O3K v0.4.0-rc.28

PP.6 Stage 2 installed-release qualification candidate. PP.6 remains BLOCKED.
This is not PP.6 final acceptance, a production release, PP.7 authorization,
production restore activation, or Araf integration. These notes prepare the
candidate only; they do not authorize a tag or publication.

## Candidate source changes

The candidate is based on the protected merge of the #1225 fix
(`fix/1225-c1-bearing-release`), followed by the version-bump alignment:

- #1225 Option A: the protected release workflow now builds C1-bearing
  releases. The release manifest carries `installation_policy_format`,
  `installation_policy_path`, and `installation_policy_authority` (key ID and
  public key only), sourced from variables on the approval-gated `release`
  environment. The packaged-path startup guard remains fail-closed and is
  strengthened: genesis startup now authenticates installed trust, and
  observer identities (the compute service user) get fail-closed
  metadata-only identity verification (SPEC-0050 §7.2.1); installation of this candidate requires the operator-controlled
  offline C1 signing ceremony (docs/operator/C1_OFFLINE_SIGNING_CEREMONY.md).
  The published one-line installer has no C1 passthrough by design.
- Qualification-only ceremony tooling (tests/pp6-c1-ceremony/) proves the
  prepare -> offline-sign -> install journey on disposable Ubuntu 24.04
  guests with a missing/tampered negative matrix; it ships no production
  key material and is not part of the release bundle.
- Cargo metadata/lock, installer pin and embedded worker asset, Helm
  appVersion, Docker build defaults, qualification fixtures, and installer
  documentation are aligned to `0.4.0-rc.28`.

The release build remains based on Debian 12 and retains the existing glibc
baseline check. The archive verifier is self-contained and must pass after
extracting the candidate archive outside the source checkout.

## Qualification scope

The proposed candidate is intended only to begin installed-release Q1/Q2
qualification on authenticated Debian 13 and Ubuntu 24.04 guests using the
explicitly authorized disposable KVM host and the read-only host preflight.
rc.27 established that a non-C1 installed release cannot start (#1225);
rc.28 exists to re-run that qualification with the C1 ceremony. E1 source
tests and E2 protected CI likewise do not substitute for E4 authenticated
installed-release evidence.

## Explicit limits

- the production bundle intentionally excludes the `o3k recovery-migrate-v2`
  command; publisher process evidence is qualification-only and is not an
  installed production migration capability;
- signed journal-v2 Phase B is an authenticated consumer only; it is not an
  operational restore capability;
- PostgreSQL restore-target mutation and controller activation are not
  authorized;
- installed-release qualification and independent security acceptance remain
  outstanding;
- persistent workloads remain separately gated on #1085/#1086 (authenticated
  PostgreSQL recovery/fencing) and #1087 (certificate
  replacement/revocation).

This does not claim full OpenStack or Horizon parity.
