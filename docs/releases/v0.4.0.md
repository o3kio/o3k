# O3K v0.4.0 — Test Use Only

This non-prerelease tag is published at the owner's direction for a single
disposable test use case. It is not a production-readiness verdict or a claim
that PP.5, PP.6, or PP.7 acceptance is complete. The GitHub non-prerelease
classification makes the exact `v0.4.0` artifact addressable; it does not
expand the approved use scope.

## Authority and use limits

The release manifest carries the lab-origin C1 installation-policy authority
`c1-policy-o3kio-lab-2026-11`, approved for disposable qualification. This
release does not establish offline production custody, a two-of-three
custodian ceremony, or production authority. Keep the lab-origin signing
material in its existing controlled custody. Do not use this release for
persistent workloads or production service.

The installer preserves the C1 fail-closed startup requirements. Installation
requires policy, state, and trust documents signed under the authority named
in the manifest. Signature verification, role separation, and startup checks
remain enabled.

## Qualification status

The owner has attested that the use cases were tested and validated. The
repository's PP.5, PP.6, and PP.7 issues remain open because the exact artifact
digests, run records, and evidence bundles have not been reconciled to their
formal acceptance matrices. This release therefore makes no complete PP.5,
PP.6, PP.7, production, HA/SLA, or broad OpenStack parity claim.

This release retains the existing limitations:

- PostgreSQL restore-target mutation and controller activation are not
  authorized;
- signed journal-v2 Phase B is an authenticated consumer, not an operational
  restore capability;
- the production bundle excludes `o3k recovery-migrate-v2`;
- persistent workloads remain blocked on authenticated backup/restore,
  controller fencing, and PKI lifecycle acceptance (#1085, #1086, #1087);
- Araf certification remains post-stable work under #1029.

## Authenticity

The protected release workflow builds from the exact approved tag, generates
the manifest, SBOM, provenance, and archive checksums, and signs the release
digest manifest with GitHub OIDC and Sigstore. The release is immutable; any
artifact change requires a new version.
