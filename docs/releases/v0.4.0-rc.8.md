# O3K v0.4.0-rc.8 — PP.4 release candidate (prerelease)

Successor candidate to `v0.4.0-rc.7` (immutable; never retagged), produced
by PP.4 (issue #973). It is a **prerelease**: it is not release-gate approved
and it makes no production, scale, or support claims beyond the evidence
attached to the PR closing #973.

## Why RC.8 exists

`v0.4.0-rc.7` was published and immediately exercised by the PP.4 fresh-host
campaigns; **both distributions failed** at the demo stage, right after
Keycloak created the demo user. The rule is never to patch a published
artifact, so RC.8 is the successor.

**RC.7 defect (fixed in RC.8).** The RC.7 change that moved the federated
subject lookup to the demo-owned environment file read that file with `sed`
*counter-intuitively before the file exists* (it is written later by
`ensure_o3k_federation`). The demo script runs with `set -e` + `pipefail`, so
`sed`'s "no such file" status aborted the whole demo stage silently — the
Keycloak admin API had already returned `201` and the following read `200`
(visible in the demo proxy access log), which is what made this hard to see.

## What changes in RC.8

- **Guarded lookup.** The federated-subject read checks file existence for
  both the demo env file and the legacy `o3kd.env` location and can no longer
  fail the script when either is absent.
- **Diagnosable, retrying Keycloak helpers.** `kc_token`, `kc_api` and a new
  `kc_user_id` now retry with bounded attempts, capture the HTTP status, and
  fail closed with a clear message plus a bounded response snippet instead of
  aborting silently under `set -e`. This also absorbs the realm-import
  readiness race seen on fresh hosts.
- **Regression gates.** `tests/pp4-araf-demo-contract.sh` now fails if the
  subject lookup loses its file guard or if the Keycloak helpers lose their
  status-reporting behaviour.

Everything in the RC.7 notes stands: the demo no longer mutates O3K-owned
configuration (systemd drop-in + demo-owned env file), federation enable is
transactional, demo/IdP secrets never travel through `argv`, the Debian 12
static-Docker path is hardened, uninstall is owner-scoped, and the packaged
demo cloud declares 30 GB of disk capacity so the TestLab VM plus user VMs
fit.

## What does NOT change

- The published `v0.4.0-rc.5`, `v0.4.0-rc.6` and `v0.4.0-rc.7` artifacts are
  untouched (immutable; never retagged).
- Araf stays pinned at `v1.0.0-rc.12` with identical digests.
- The PP.2 canonical bootstrap contract, the upgrade fence, and the O3K
  readiness independence boundary are unchanged.

Final PP.4 fresh-host campaign evidence is recorded separately; this note
makes no claim beyond the code and contract changes above.
