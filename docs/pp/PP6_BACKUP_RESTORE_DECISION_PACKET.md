# PP.6 backup and restore decision record for approval

**Revision:** 2026-10-17
**Status:** Concrete recommendations submitted for explicit human decisions; none
are accepted. ADR-0189 and SPEC-0050 remain Proposed. This record does not
authorize production backup/restore or PKI implementation.

**Issue authority:** #975, #640, #1084–#1087, and #1098.
**Profiles:** single-site `o3k-demo-v1` with SQLite and
`o3k-small-edge-v1` with PostgreSQL 16. External VM disks, external storage
payloads, and external-hosted service databases remain outside this recovery

## D1–D13 — concrete recommendations

| ID | Proposed disposition and recommendation / implementation parameters | Security and operational impact | Authority, review status, unresolved dependency |
|---|---|---|---|
| D1 Artifact format and authenticity | **Amend.** Versioned regular-file container. Generate a fresh 256-bit CSPRNG content key per artifact; encrypt each allowlisted member with AES-256-GCM and a unique 96-bit CSPRNG nonce. Bind member name, plaintext length, format version, profile, site ID, and artifact ID as RFC 8785 canonical AAD. Sort members by UTF-8 path bytes and reject duplicate paths. Enforce nonce uniqueness per content key across the complete artifact and reject duplicate nonce fields before decryption. The Ed25519 signing key ID must resolve to a non-revoked public key pinned by the separately authenticated trust store. Signature input: `O3K-PP6-BACKUP-MANIFEST-V1\0 || u64be(manifest_length) || canonical_manifest_without_signature || concatenated_member_digests`; each digest entry is `u32be(path_byte_length) || path_bytes || SHA256(ciphertext_and_tag)` in UTF-8 path order. Use RFC 8785 canonical UTF-8 JSON and reject duplicate keys/noncanonical forms. HPKE Base mode RFC 9180 using X25519/HKDF-SHA256/AES-256-GCM wraps the content key to the operator recovery public key; `info` is UTF-8 `O3K-PP6-ARTIFACT-KEY-WRAP-V1\0`, and AAD is canonical JSON containing format version, profile, site ID, artifact ID, and recipient key ID. Record HPKE `enc` and wrapped ciphertext exactly as specified by RFC 9180; signature covers both and recipient key ID. Only structural metadata is cleartext; no tenant rows, credentials, provider payloads, or private keys. No compression. Reject unknown versions/algorithms, invalid signatures, bad tags, and malformed lengths before extraction. | Provides confidentiality and source authenticity without putting a secret or unspecified KMS dependency on the controller. Trust-root pinning and revocation are mandatory; AEAD/checksums alone do not establish provenance. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Review must accept exact serialization, signed inputs, HPKE context, and trust-root/revocation path. |
| D2 Key custody, recovery, rotation | **Amend.** Use operator-held asymmetric keys for both profiles. Generate distinct X25519 recipient, Ed25519 artifact-signing, and Ed25519 journal-signing key pairs on a disconnected, access-controlled Linux operator workstation. Keep private keys off controller hosts and backup destinations. Store two copies on separate offline removable media with ext4 inside LUKS2 AES-256-XTS volumes. Recommend cryptsetup Argon2id, 1 GiB memory, parallelism 4, and a 2-second format-time target for operator usability, not as a security threshold; record actual LUKS2 header parameters with `luksDump`. The KDF policy may raise but must never silently lower memory or parallelism. Label each XOR share with custodian ID and share index, include a printed SHA-256 corruption check, and independently verify the reconstructed passphrase by opening the volume before relying on it; the LUKS2 keyslot remains the authoritative verifier. Generate a 256-bit CSPRNG volume passphrase and split it into two equal XOR shares; separate named custodians hold one share each. Store Ed25519/X25519 keys as PKCS#8 DER inside the encrypted volume. Verify each pair against a separately held public-key fingerprint card. Recovery requires both custodians, read-only media mount, fingerprint verification, and a disposable restore drill before operational use. Pin recipient and verification public keys by key ID through separately authenticated installation. Retain old recipient private keys and signing public keys while any artifact under them remains in retention; revoke keys only through an explicit authenticated trust-store update. Missing keys/copies fail closed. No KMS is required by v1. | Avoids cloud/KMS availability and account dependencies during disaster recovery. Dual-person offline custody adds operational work; loss of both media or either passphrase share makes artifacts unrecoverable. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Reviewer must approve Argon2id parameters, cryptsetup/workstation versions and compatibility procedure, custody locations, two-custodian control, retention/rotation, revocation, media integrity, and loss/recovery consequences. Exact values are recorded before implementation; implementation may not choose them. |
| D3 PKI issuer and agent credentials | **Accept as written.** Never include controller issuer or agent private keys in artifacts. Replace the issuer during fresh-host restore, run a new trust ceremony, and re-enroll agents. Before activation, replace old issuer roots in every API, controller, agent, and provider trust path; invalidate cached trust material; preserve durable revocations; and prove a stale credential signed by the old issuer is rejected at each verifier. Regenerate controller runtime identity, sessions, and credentials. | Replacement avoids restoring a revoked credential to validity and avoids turning backup artifacts into fleet credentials. Re-enrollment creates a planned recovery outage and must be included in runbooks. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). #1087 depends on accepted issuer replacement, revocation and re-enrollment behavior. |
| D4 Consistent capture boundary | **Amend.** v1 backup is offline for both profiles. Stop every `o3kd` instance and hold an exclusive OS lock on the O3K data directory before capture; retain it through verified publication or safe abort. **The current control-plane code does not establish this as a startup-lock invariant.** Adding and testing the startup exclusion is a prerequisite contract/implementation change; until then, backup must not claim that the lock prevents a supervisor from restarting `o3kd`. SQLite uses the supported SQLite backup API against the file-backed database. PostgreSQL uses PostgreSQL 16 `pg_dump -Fc` from a consistent snapshot while every O3K controller instance is stopped. The database and restored schemas must be exclusively O3K-owned, with no shared application schema or unrelated writer role; verify there are no active O3K writer sessions and prevent writer login for the capture interval. Bind database and files to one capture generation, schema/migration identity, profile, and site. Discard all staging if the lock, generation, or ownership proof changes. | The stopped process is the cross-file consistency barrier and avoids a more complex online admission/drain protocol. Evidence must prove every controller instance is stopped and supervisors cannot restart one during capture. The controller API is unavailable during capture. Workload data-plane services must be shown to continue safely while `o3kd` is stopped for each profile. | Architecture authority: senolcolak (**PENDING**); independent security authority: unassigned, distinct person required (**PENDING**). Required evidence: implemented lock identity/startup exclusion, cross-file generation, profile-specific workload data-plane behavior, and bounded-profile capture duration. |
| D5 In-flight Operations | **Accept as written.** At shutdown, preserve canonical operation IDs and phases. Terminal operations remain terminal; nonterminal operations are recorded as unresolved and require observe-before-retry after restore. A timeout or shutdown does not become a failure classification and backup never replays a mutation. | Preserves idempotency and compensation authority; unresolved provider outcomes may require operator intervention. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Depends on D4 boundary and existing operation/reconciliation authority. |
| D6 Stable and regenerated identities | **Accept as written.** Preserve site/installation ID, canonical resource IDs, owner/security scopes, provider mappings, bootstrap principal identity, audit history, and revocation records. Regenerate controller process/session identity, leases, controller credentials, and host-local agent credentials. Never restore an active lease or private credential. | Stable resource identities preserve references; fresh controller and host credentials prevent a copied source from retaining authority. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Implementation requires a reviewed schema/migration map for every preserved and regenerated value. |
| D7 Source exclusion and target fencing | **Amend.** Before any restored canonical database/file mutation or provider/API action, an authorized operator must prove source exclusion using an independently administered power-off or network-isolation control that blocks API, control-plane, and provider paths. Record the control-plane evidence and actor. SQLite target additionally takes the exclusive startup/data lock. Both targets invalidate restored leases and persist a fresh ownership epoch greater than the restored epoch before activation. PostgreSQL target additionally proves fresh database ownership and target-only writer access; lease expiry alone is insufficient. Unreachable source without independent fence evidence means target stays inactive. Two-person attestation alone is not a substitute for independent evidence. | Prevents split brain and stale source mutation. A source that cannot be independently fenced blocks restore; operators need access to the independent host/network/power control plane. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). No concrete supported out-of-band fencing backend is currently named for either profile. Reviewer must name the authorized operator role, exact supported power/network control, evidence format and freshness check, and source/target identity binding for each profile. Evidence must prove controller, supervisor, and local-provider paths cannot resume. Confirm the unreachable-source fail-closed rule. |
| D8 Restore journal and reservation | **Amend; implementation remains blocked on the journal-signing interaction.** Journal is outside the target database in a dedicated owner-only directory on Linux ext4 over a local block device; reject NFS, overlay/ephemeral filesystems, and unverified CSI/network volumes. Hold the OS `flock(2)` exclusive lock from reservation through activation. Sign exact bytes `O3K-PP6-RESTORE-JOURNAL-V1\0 || u64be(record_length) || RFC8785(record_without_signature)` with Ed25519; encode its 64-byte signature as unpadded base64url. Each record includes a sequence starting at 1 and increasing exactly by one, prior signed-record SHA-256, artifact digest, site/source/target identities, operation/step IDs, and phase. Chain each prior record’s canonical bytes plus signature; reject gaps, rollback, and forked histories. Reserve only an empty, newly created target under an exclusive OS lock throughout restore; inspect and preserve any foreign/nonempty state without mutation. Use file fsync, atomic same-filesystem rename, then directory fsync before acknowledging a phase. Verify the entire signature/hash chain and legal transition before acting. Phases: `PREFLIGHTED → SOURCE_FENCED → TARGET_RESERVED → STAGING → DATABASE_RESTORED → FILES_RESTORED → TARGET_FENCED → STARTED → RECONCILED → COMMITTED`; safe pre-mutation abort is `ABORTED`, known partial is inactive `FAILED_RECOVERABLE`, and unknown outcome/lock loss/conflict is `QUARANTINED`; only verified recreation/discard permits `DISCARDED`. Restart must reacquire the lock, inspect journal and target, then observe before retry. It never repeats solely because a response was lost. | A durable signed journal supports crash recovery and detects unauthorized edits, but an offline signing key cannot silently sign automated phase transitions. v1 must pause for an authorized operator to sign each transition; no key may be copied to the target. This is deliberately conservative and may make restore interactive. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). **Unresolved blocker:** define authenticated transition-record transport; bind each signature to operator identity, artifact digest, source and target identities, expected prior sequence/hash, and exact next phase; prevent replay; verify the target/artifact context on the offline signing workstation; define how signatures are returned and authenticated. The approved signing tool and human action for every transition must be named before implementation, or an alternative protected signing mechanism/custody model must be explicitly selected. Recommend Linux ext4 on local block storage, `flock(2)`, owner-only directory/file modes, file fsync, same-directory atomic rename, and parent-directory fsync. On restart, a free OS lock is not sufficient to delete a prior journal: an authorized operator must prove the prior process is stopped, inspect target and journal, then resume or quarantine. Exact supported kernel/filesystem versions, crash-durability evidence, and stale-lock operator role remain approval parameters. No implementation may invent these. |
| D9 Artifact bounds/publication | **Amend.** Closed regular-file allowlist; reject links, devices, sparse files, path traversal, duplicate names, and unknown members. No-follow private staging; atomic same-filesystem publication only after all members, metadata, signatures, and tags verify; no compression. Maximum 64 members, depth 8, path length 1024 UTF-8 bytes, 1 GiB/member, 4 GiB aggregate plaintext, 16 MiB manifest, 64 MiB total format overhead, and 5 GiB complete artifact. Preflight measures the complete allowlisted source set, rejects any member above 1 GiB or aggregate plaintext above 4 GiB, and reserves `max(2 × measured source bytes + 1 GiB, 5 GiB + 1 GiB)`. The 5 GiB artifact maximum is the conservative pre-capture upper bound; enforce the computed reservation as a staging quota so capture aborts before exceeding it. After serialization, verify exact complete artifact size is at most 5 GiB before publication. If the computed reserve exceeds 8 GiB or destination capacity is insufficient, fail before capture. Never cap a reservation below the computed need; reserve the full amount before capture or restore. | Limits archive abuse and disk exhaustion and prevents partial artifacts from appearing complete. Limits may constrain larger installations and require adequate free-space checks. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Reviewer must confirm measured profile sizes and that the reserve formula can accommodate the encrypted artifact and temporary files; otherwise amend numeric values explicitly. |
| D10 PostgreSQL ownership/object policy | **Accept with exact v1 allowlist.** PostgreSQL 16 only; `pg_dump -Fc`, restore with `pg_restore --exit-on-error --no-owner --no-acl` into a fresh empty database. Restore under installation-provisioned non-superuser schema-owner role. Do not restore cluster roles/globals, passwords, tablespaces, ACLs, owners, or artifact-defined grants. Reapply grants from trusted installation policy. v1 extension allowlist is empty. The exact migration-derived inventory includes all user tables, sequences, indexes, constraints, defaults, views, and migration-created functions/triggers, and distinguishes them from PostgreSQL-native catalog objects generated by the server/tool. Accept no unlisted user object. | Prevents artifact-controlled privilege escalation and cluster-wide mutation. Requires object inventory to track accepted migrations and makes extension use a separately reviewed contract change. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Reviewer must approve exact role/database/schema grants and object-inventory revision before #1085. |
| D11 Interruption and post-start failure | **Accept as written.** Before activation, known partial mutation is inactive `FAILED_RECOVERABLE`; unknown outcome, lock loss, or conflict is `QUARANTINED`. After startup, stop/fence dispatch on failure, preserve operation IDs, observe provider/repository state before retry, and use existing reconciliation authority. No in-place repair in v1; only verified discard/recreation reaches `DISCARDED`. Journal states are not canonical Operations or controller state. | Avoids duplicate provider mutations and protects canonical state under ambiguous outcomes. Some cases require explicit operator intervention and a newly reserved target. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). Depends on D7–D8 and accepted restart/failure tests in disposable SQLite and PostgreSQL environments. |
| D12 Public interface | **Accept as written.** #1084–#1086 add no unapproved public CLI or API. The restore flow must not be exposed through an implementation-only command. | Architecture authority: senolcolak (PENDING); independent security authority: unassigned and must be a distinct person (PENDING). ## Dependencies and implementation gate

The following decisions are independent blockers and must not be inferred from
other approvals:

1. **D8:** signed journal transition mechanism, authenticated offline signing transport, supported local ext4/kernel behavior, and stale-lock recovery authority.
2. **D7:** exact fencing control, fresh verifiable evidence, source/target identity binding, and authorized actor for each profile; source-unreachable disposition.
3. **D9:** measured artifact sizes and accepted staging/free-space limits.
4. **D10:** exact least-privilege PostgreSQL grants and migration-derived object
   inventory.
5. **D2:** exact storage-encryption parameters/tool versions, offline custody, rotation, revocation, media integrity, and recovery procedure.
6. **D12:** approved operator path needed to exercise exact-release recovery.

No production backup/restore or security-sensitive PKI implementation may begin
until the relevant decisions above are explicitly accepted in ADR-0189 and
SPEC-0050. A reviewer must copy the accepted or amended values, both role
decisions, date, and exact source revision into those normative documents.
Implementation follows the existing issue order: #1084 SQLite artifact, #1085
PostgreSQL adapter, #1086 fresh-host recovery, then dependent #1087 PKI and #1098
upgrade/recovery work. This packet does not accept evidence, claim PP.6
completion, alter PP.5, or authorize PP.7.
