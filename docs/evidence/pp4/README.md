# PP.4 evidence (o3kio/o3k#973)

Durable, redacted evidence has two explicitly classified inputs. Historical
one-line O3K + Araf campaign output is preserved as PP.4A (#1029) evidence;
it is not rewritten or promoted to the PP.4 Core completion gate. PP.4 Core
uses a separate native-first campaign and bounded Horizon witness. A Core
manifest must never contain an Araf readiness assertion.
Raw campaign logs are large and stay local/gitignored under
`target/pp4-campaign/`; this directory keeps the immutable metadata needed to
verify what was actually tested, against which exact artifacts.

Per Core campaign (added by the campaign run; absent until the campaign
completes):

- `manifest-core-ubuntu-24.04.json` / `manifest-core-debian-12.json` —
  machine-readable campaign id, host OS/kernel/CPU/KVM/boot IDs, exact O3K
  release/source SHA, native Operation/server/network/port/provider/domain
  IDs, guest-boot evidence, native↔OpenStack identity mapping, pinned
  Horizon artifact identity, Horizon result/matrix, lifecycle/reboot and
  cleanup cases, SHA-256 of every raw evidence file, and known limitations.
  No Araf fields are required or synthesized.
- `manifest-ubuntu-24.04.json` / `manifest-debian-12.json` — historical
  Araf-integrated campaign manifests retained as PP.4A input.

Manifests are generated by `tests/pp4-campaign/make-manifest.py` from the
campaign evidence directory. To verify a committed manifest against local raw
evidence:

```sh
python3 tests/pp4-campaign/make-manifest.py ubuntu target/pp4-campaign/ubuntu/evidence-final \
  v0.4.0-rc.8 <source-sha> | diff - docs/evidence/pp4/manifest-ubuntu-24.04.json
```

Acceptance areas and the evidence files each campaign produces:

| Area | Evidence |
| --- | --- |
| one-line install -> O3K + Araf ready | `01-one-line-install.log`, `02-success-output.txt`, `03-timestamps.env`, cases I3-I14 |
| demo never mutates O3K-owned config (rc.7 regression) | `12b-*`, `12b2-*`, `27b-*`, cases I15-I16, C8 |
| demo disk capacity fits a second VM | `12d-demo-disk-capacity.txt`, case I17 |
| real browser E2E (tenant + operator) | `05-browser-e2e.log`, browser screenshots (local), `23-browser-relogin.log` |
| console UI deletion lifecycle on a canonical server | case `PP4-UI-DELETE`, `05-browser-ids.env` |
| classified gaps (truthful failures) | `35-classified-gaps.txt`, `21-network-provider-posture.txt`, `21e-compat-vs-native-inventories.txt` |
| cross-interface canonical truth (native <-> CLI) | `13-*`-`18-*`, cases A-gap, B1-B3, C1-C3, D1-D3, G1 |
| OpenStack CLI witness (unmodified) | `08-*`, `14-*`, cases I10-I11, B2 |
| OpenTofu supplemental smoke (provider 3.4.0) | `20-tofu-*.log`, cases T1-T2 |
| reboot recovery + rerun convergence | `22-*`-`25-*`, boot-id files, cases R1-R3 |
| failure/recovery matrix | `23-browser-relogin.log`, `26-*`, cases F1-F4 |
| cleanup / foreign-state preservation | `27-*`-`31-*`, cases C1-C8 |
| secret scans (browser + CLI + journals) | `17-secret-scan.txt`, `32-secret-scan-phase2.txt`, case SEC1 |
| Horizon (bounded external witness) | `30-horizon-summary.txt` plus `horizon-artifact.yaml`; exact image digest and OS matrix are mandatory for a Core manifest |

Known limitations are recorded inside each manifest. Campaigns that did not
run (or failed) have no manifest here on purpose.
