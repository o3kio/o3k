# PP.4 evidence (o3kio/o3k#973)

Durable, redacted evidence for the PP.4 one-line O3K + Araf demo acceptance.
Raw campaign logs are large and stay local/gitignored under
`target/pp4-campaign/`; this directory keeps the immutable metadata needed to
verify what was actually tested, against which exact artifacts.

Per campaign:

- `manifest-ubuntu-24.04.json` / `manifest-debian-12.json` — machine-readable:
  campaign id, host OS/kernel/CPU/KVM/boot IDs, installed O3K version +
  source SHA, pinned Araf version + source SHA, canonical resource IDs used by
  the cross-interface tests, T0–T5 install timestamps, every acceptance case
  with PASS/FAIL, SHA-256 of every raw evidence file, and known limitations.
  No secrets, no log content.

The manifests are generated by `tests/pp4-campaign/make-manifest.py` from the
campaign evidence directory. To verify a manifest against local raw evidence:

```sh
python3 tests/pp4-campaign/make-manifest.py ubuntu target/pp4-campaign/ubuntu/evidence-final \
  v0.4.0-rc.6 <source-sha> | diff - docs/evidence/pp4/manifest-ubuntu-24.04.json
```

Acceptance ledger (both distros, fresh hosts, public artifacts):

| Area | Where proven |
| --- | --- |
| one-line install -> O3K + Araf ready | cases I3–I13, T0–T5 in each manifest |
| real browser E2E (tenant + operator) | `05-browser-e2e.log` SHA in manifest; screenshots (local) |
| cross-interface canonical truth (A–D) | cases A1–A3, B1, C1–C2, D1–D2 |
| OpenStack CLI witness (unmodified) | cases I10–I11, A2, C1–C2, D1–D2 |
| OpenTofu supplemental smoke (provider 3.4.0) | cases T1–T2 |
| reboot recovery + rerun convergence | cases R1–R2, boot IDs in manifest |
| failure/recovery matrix | cases F1–F4 |
| cleanup / foreign-state preservation | cases C1–C6 |
| secret scans (browser + CLI + journals) | cases SEC1, C6, `17-secret-scan.txt` SHA |
| Horizon (optional witness) | `30-horizon-summary.txt` SHA (Ubuntu campaign) |

Known limitations are recorded inside each manifest.
